# v2.0 — Grounded & Explainable RAG Core

**Freeze Date:** 14 February 2026
**Tag:** `v2.0`

---

## 1. Overview

Version **v2.0** freezes the core architecture of the local-first RAG system after completing:

* Retrieval contract migration
* Grounding enforcement
* Confidence modeling
* Provenance preservation
* Test stabilization
* Explainability integration

This version represents the transition from a functional RAG prototype to a **grounded, deterministic, explainable system**.

---

## 2. Architectural Guarantees

### 2.1 Retrieval Contract (Locked)

Retrieval now returns structured objects:

```python
{
    "chunk_id": str,
    "section_id": str,
    "document_id": str,
    "text": str,
    "similarity": float,
}
```

Tuple-based retrieval `(text, score)` has been permanently removed.

**Guarantees:**

* Retrieval preserves identity
* All evidence is traceable
* Contract enforced by tests

---

### 2.2 Grounding Enforcement

The system enforces grounding before LLM invocation:

1. Retrieve top-k chunks
2. Evaluate similarity threshold
3. If insufficient evidence → block LLM call
4. Return deterministic IDK response

The LLM is never called on weak retrieval.

---

### 2.3 Confidence Model

Confidence is now formalized as a structured object:

```python
ConfidenceReport:
    confidence_level: NONE | LOW | MEDIUM | HIGH
    confidence_score: float (internal, non-probabilistic)
    rationale: List[str]
    retrieval_stats: Dict
```

Confidence represents:

> Evidence support strength, not probability of correctness.

Confidence incorporates:

* Maximum similarity
* Number of retrieved chunks
* Corpus profile (small vs large)
* Extractive-only enforcement
* Relevance gate outcome

---

### 2.4 Provenance & Explainability

Every answer includes structured evidence:

* File path
* Document name
* Section title / path
* Chunk ID
* Similarity (internal)

Two visibility levels exist:

**User Mode**

* Document + section
* Confidence level
* Human-readable rationale

**Debug Mode**

* Full provenance
* Similarity scores
* Character offsets
* Retrieval stats

---

### 2.5 Safety Boundaries

v2.0 enforces the following invariants:

* Retrieval occurs before generation
* Confidence computed before LLM invocation
* Similarity scores never exposed to LLM
* Hard relevance gating
* Post-generation answer-level gate
* Deterministic IDK behavior
* No silent hallucination paths

---

## 3. Testing & Stability

### 3.1 Contract Enforcement

* Retrieval shape locked (dict-based)
* Registry integration validated
* No legacy tuple support
* No fake IDs in tests
* Exception-safe execution paths

### 3.2 Fixture-Based Test Infrastructure

* Global test state removed
* Pytest fixtures used for:

  * Real chunk loading
  * Retrieval item mocking
  * Project path injection

Test suite reflects production behavior.

---

## 4. Behavioral Guarantees at v2.0

At this version:

* Weak queries → deterministic refusal
* Strong evidence → grounded response
* Ambiguous context → safe blocking
* Confidence never implies probability
* All answers are traceable to source

The system is:

* Deterministic
* Explainable
* Contract-locked
* Grounded

---

## 5. Explicit Non-Goals

v2.0 does NOT include:

* Multi-modal input
* PDF-native parsing
* UI layer
* Agents
* Probabilistic calibration
* External evaluation tooling

This version freezes the **core trust architecture**, not feature breadth.

---

## 6. Known Limitations

* Confidence score is heuristic (not calibrated)
* Threshold tuning not statistically validated
* Line-level provenance not implemented
* Clarification flow not implemented
* No user feedback loop

These are deferred to future versions.

---

## 7. Upgrade Path to v2.1

The next version (v2.1) will focus on:

* Confidence presentation policy
* Clarification flow for ambiguous queries
* Source display refinement
* Threshold calibration tools
* UX-layer improvements

No architectural rewrites are planned beyond this point.

---

## 8. Final Statement

v2.0 marks the completion of the system’s core trust boundary:

> The assistant answers only when grounded, explains why it answered, and refuses deterministically when evidence is insufficient.

This version establishes a stable foundation for future feature expansion without compromising safety or interpretability.
