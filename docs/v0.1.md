# Project Freeze — v0.1

## What v0.1 Represents

**v0.1** marks the first **complete, runnable, end-to-end RAG system** built with:

* clean architecture
* explicit separation of concerns
* real local + online LLM support
* no mock components
* no hidden magic

It is a **functional milestone**, not a production milestone.

---

## Functional Scope of v0.1

### ✅ Implemented and Working

#### 1. Offline Indexing (Build-Time)

* Document ingestion from `data/raw/`
* Chunking and embedding
* FAISS index creation
* Immutable build artifacts in `data/indexes/`

#### 2. Retrieval (Query-Time)

* FAISS-based semantic search
* Forced top-k ranking
* Disk-backed index loading
* No index mutation at runtime

#### 3. Prompt Assembly

* Centralized prompt logic
* Strict “answer only from context” instruction
* Optional system instruction hook

#### 4. LLM Infrastructure

* Local LLM via Ollama
* Online LLM via OpenAI-style API
* Unified `BaseLLM` contract
* Config-driven provider + model routing
* Secrets handled via `.env`

#### 5. End-to-End RAG Runner (STEP 13)

* `run_rag(query)`
* Retrieval → prompt → LLM → answer
* No UI, no server, no agents

---

## What v0.1 Explicitly Does NOT Guarantee

This is important to state clearly.

### ❌ Not Guaranteed in v0.1

* Grounded answers
* Hallucination prevention
* Relevance validation
* Retrieval quality gating
* “I don’t know” enforcement
* Answer correctness metrics

These are **known limitations**, not bugs.

## Architectural Integrity at v0.1

At freeze time, the system satisfies:

* ✔ Build-time vs query-time separation
* ✔ Capabilities vs orchestration separation
* ✔ Single responsibility per module
* ✔ Fail-loud behavior
* ✔ Local-first execution
* ✔ Forward-compatible extension points

No shortcuts were taken that would block future correctness work.
